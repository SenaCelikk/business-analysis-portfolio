# Post-Checkout & Payment Experience

## Overview

### Context

At LC Waikiki, I worked on mobile features related to the post-checkout and payment experience.

The work involved collaboration between Product Owners, Design, Backend, Android, and iOS teams.

Although my official role was Software Engineer, I was involved in activities that went beyond implementation, including requirements clarification, functional analysis, API analysis, edge-case definition, refinement, cross-team coordination, and UAT.

### My Role

My responsibilities included:

- Clarifying product and business requirements
- Translating requirements into functional and technical requirements
- Defining expected client-side behavior
- Analyzing API request and response structures
- Identifying edge cases and validation scenarios
- Documenting requirements and scenarios in Jira
- Participating in backlog refinement
- Coordinating related work with the iOS team
- Supporting UAT and feature validation

## Business Context

The work covered parts of the customer journey after checkout, including payment-related flows and integrations.

The goal was to make the mobile experience behave consistently across different payment scenarios while ensuring that the client application correctly handled backend responses, validation rules, and exceptional cases.

Payment-related integrations included Masterpass, MobileExpress, and SDK-based integrations.

> Company-specific implementation details and internal information have been anonymized.

## Requirements Analysis

### Requirement Clarification

I worked with Product Owners, Design, Backend, and mobile teams to clarify requirements before implementation.

This included identifying:

- Expected user behavior
- Required application states
- Backend dependencies
- API response scenarios
- Validation rules
- Error and exceptional cases
- Differences between Android and iOS implementations

### Functional Analysis

I translated product requirements into behavior that could be implemented and validated by the development teams.

For example, requirements were broken down into:

- User actions
- Expected application behavior
- API interactions
- Success scenarios
- Error scenarios
- Edge cases
- Validation conditions

## API & Technical Analysis

I analyzed API request and response structures to understand how backend data affected the mobile experience.

This helped define:

- Which response fields were required
- How different response states should be handled
- What the mobile application should display
- How error and exceptional scenarios should behave

The analysis was documented and discussed with the relevant teams during refinement.

## Edge Cases

Part of the analysis involved identifying scenarios outside the main happy path.

Examples included:

- Unexpected API responses
- Missing or incomplete data
- Payment-related errors
- Different payment integration behaviors
- Invalid or unexpected application states
- Client-side validation scenarios

## Agile Collaboration

I participated in refinement discussions with Product and engineering teams.

The discussions helped ensure that requirements were sufficiently clear before development and that dependencies between Android, iOS, Backend, Design, and Product were understood.

## UAT & Validation

I also participated in feature validation and UAT.

This involved checking whether the implemented behavior matched the agreed requirements and identifying issues that needed further clarification or correction.
